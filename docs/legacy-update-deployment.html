旧版本升级到新版本

HuanXing-Claw（Electron）和 HuanXing-Hermes（Tauri）统一采用“旧站点只负责发现更新，火山云 TOS 负责实际下载”的迁移方式。

适用仓库：nevermorewish/HuanXing-Claw、nevermorewish/HuanXing-Hermes

先看结论： Linux 服务器不再保存新的安装包、压缩包或 blockmap。Linux 服务器只保存旧版本仍会请求的更新清单；清单中的安装包 URL 必须是火山云 TOS 的 HTTPS 地址。

一、升级链路

旧版本客户端
    |
    | 请求旧地址
    v
Linux / Nginx 旧站点
    |
    | 返回 latest.yml / latest-mac.yml / latest.json
    | 清单中的 url 已指向 TOS
    v
火山云 TOS
    |
    | 下载新版安装包
    v
新版客户端

三、Linux 服务器需要部署什么

必须部署

  1. 旧版本兼容清单：Claw 的 latest.yml、可选的 latest-mac.yml；Hermes 的品牌 latest.json。
  2. Nginx 或其他 HTTPS 静态文件服务，使旧地址可以被大陆网络访问。
  3. 每次新版本发布后，用原子替换方式更新清单，避免客户端读到半个文件。

不需要部署

  • 新的 Windows .exe、macOS .dmg、portable .zip。
  • .blockmap 文件。
  • Hermes 的 TOS 安装包副本。

这些文件由 GitHub Actions 上传到 TOS。旧站点只做升级跳板，避免同一安装包在 Linux 服务器和 TOS 存两份。

推荐目录结构

/www/wwwroot/ai.fengchiyun.com/
└── downloads/
    ├── fengchiclaw/
    │   └── latest/
    │       ├── latest.yml
    │       └── latest-mac.yml
    ├── huanxingclaw/
    │   └── latest/
    │       ├── latest.yml
    │       └── latest-mac.yml
    ├── frogclaw/
    │   └── latest/
    │       ├── latest.yml
    │       └── latest-mac.yml
    └── fengchihermes/
        └── latest.json
部署路径注意：工作流现在同时兼容两种配置：LINUX_DEPLOY_PATH=/www/wwwroot/ai.fengchiyun.com，或者已经配置成 /www/wwwroot/ai.fengchiyun.com/downloads。不要在工作流和 Secret 中重复追加 /downloads。

Nginx 最小配置

server {
    listen 443 ssl;
    server_name ai.fengchiyun.com;

    root /www/wwwroot/ai.fengchiyun.com;

    location /downloads/ {
        try_files $uri =404;
        add_header Cache-Control "no-store, no-cache, must-revalidate" always;
        add_header Access-Control-Allow-Origin "*" always;
        types {
            application/json json;
            text/yaml yml;
        }
    }
}

清单建议禁用缓存；TOS 版本目录中的安装包使用不可变缓存。HTTPS 证书、DNS 解析和防火墙 443 端口必须正常。

四、GitHub Actions 需要配置什么

配置项用途
LINUX_DEPLOY_HOSTLinux 服务器地址，例如 43.224.248.112
LINUX_DEPLOY_PORTSSH 端口，通常为 22
LINUX_DEPLOY_USER用于写入清单目录的 SSH 用户
LINUX_DEPLOY_PATH网站根目录，或已经存在的 downloads 目录
LINUX_DEPLOY_KEYGitHub Actions 使用的 SSH 私钥
LINUX_DEPLOY_KNOWN_HOSTS推荐配置，避免 SSH 主机指纹被伪造

Linux 用户只需要对清单目录拥有写权限，不需要给 Actions 整台服务器的无限权限。

五、正式发布步骤

  1. 提升版本号。版本必须大于用户当前版本。例如用户已是 Claw 0.4.25，新包必须是 0.4.26；同版本不会触发升级。
  2. 构建并上传 TOS。CI 生成安装包、blockmap 和清单，把安装包写入 TOS 的 latest 与 releases/v<version> 目录。
  3. 同步旧版清单。Claw 上传 yml；Hermes 上传品牌 JSON。清单里的所有安装包 URL 必须是 TOS HTTPS URL。
  4. 验证公开地址。确认旧地址能返回 200、版本号是新版本、没有相对文件名。
  5. 用真实旧安装包测试。至少测试一个旧版 Windows 客户端覆盖升级；确认升级后下一次检查直接访问 TOS。

七、常见错误

现象原因处理
URL 404写成了 latest,yml，或目录层级错误使用 latest.yml，检查 downloads/<brand>/latest/
返回旧版本旧 Linux 文件没有覆盖，或写到了重复的 downloads/downloads检查 LINUX_DEPLOY_PATH，查看文件 Last-Modified
清单显示新版但下载失败清单仍使用相对 exe 文件名，或 TOS 对象不存在清单 URL 必须是完整 TOS HTTPS URL，并检查 TOS 对象
客户端没有弹升级新旧版本号相同，或新版本号低于本地版本提升版本号，禁止使用同版本覆盖发布
Actions 绿色但公开 URL 未变化上传到了错误的服务器目录，或 CDN/代理缓存用 curl -I 检查 Last-Modified；确认部署根目录不要重复追加 downloads
TOS 上传长时间无响应对象存储网络或 PUT 权限异常检查 TOS 公网 PUT 权限、网络连通性和 Actions 日志；不要把旧清单提前标为完成
本文描述的是静态清单桥接方案。旧版本升级完成后，后续安装包请求应全部落到火山云 TOS；Linux 旧站点只保留清单，不作为新安装包源。
